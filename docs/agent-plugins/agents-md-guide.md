# AGENTS.md ガイド

このガイドは、本プロジェクトで AI コーディングエージェントへ作業方針を伝えるための `AGENTS.md` の役割、Codex による読み込み規則、記述方法、検証方法を説明します。

`AGENTS.md` は Codex が対応するプロジェクト指示ファイルです。Agent Plugins 1.0.0 のポータブルなコンポーネントではないため、Agent Plugin のマニフェストや Skill とは役割を分けて管理します。

本プロジェクトの `AGENTS.md` は、基本的な記述例を示すための簡単なサンプルです。実運用に必要な規則を網羅するものではありません。

## 1. `AGENTS.md` の目的

`AGENTS.md` には、「このリポジトリではどの環境を使うか」「変更前後に何を確認するか」「どのコマンドで検証するか」といった、プロジェクト内で繰り返し適用したい作業指示を記述します。

本プロジェクトでは、リポジトリルートの [`AGENTS.md`](../../AGENTS.md) に次の内容を定義しています。

- Java 21 と Gradle Wrapper を使用すること
- 関係するファイルを確認し、必要最小限の編集を行うこと
- 関係のないファイルや生成ファイルを変更しないこと
- 必要に応じてテストやチェックを実行すること
- ドキュメントを日本語で記述すること

このサンプルでは、プロジェクト概要、簡単な作業ルール、確認コマンド、作業完了時の報告だけを記述しています。実際のプロジェクトでは、必要に応じて固有のルールを追加してください。

## 2. Agent Plugins 1.0.0 との関係

`AGENTS.md` と Agent Plugins の各ファイルは、次のように役割が異なります。

| ファイル | 役割 | Agent Plugins 1.0.0 のポータブルコア |
| --- | --- | --- |
| `AGENTS.md` | Codex にプロジェクト内の作業方針を伝える | 含まれない |
| `plugin.json` | Agent Plugin の識別情報とメタデータを定義する | 必須 |
| `skills/<skill-name>/SKILL.md` | 特定のタスクで利用する手順や専門知識を提供する | 任意 |
| `mcp.json` | MCP サーバー接続を定義する | 任意 |

Agent Plugins 1.0.0 が標準化するポータブルなコンポーネントは Agent Skills と MCP サーバーです。`AGENTS.md` を配置しても Agent Plugins 準拠の要件にはならず、Agent Plugins に対応していても `AGENTS.md` を解釈しないクライアントがあります。

反対に、`AGENTS.md` へ Skill や MCP サーバーをインライン定義することもできません。それぞれを所定のファイルへ分離します。Agent Plugins の構成については、[Agent Plugins 1.0.0 標準化ガイド](agent-plugins-1.0.0-guide.md)を参照してください。

## 3. このプロジェクトでの配置

現在の関連ファイルは次の位置にあります。

~~~text
spring-boot-dev-tooling-lab/
├── AGENTS.md
├── plugin.json
├── skills/
│   └── fix-sonarlint-issues/
│       ├── SKILL.md
│       └── agents/
│           └── openai.yaml
└── docs/
    └── agent-plugins/
        ├── agent-plugins-1.0.0-guide.md
        └── agents-md-guide.md
~~~

ルートの `AGENTS.md` はリポジトリ全体へ適用します。特定のサブディレクトリだけに追加の規則が必要になった場合は、そのディレクトリへ `AGENTS.md` または `AGENTS.override.md` を追加できます。

## 4. Codex の読み込み規則

Codex は作業開始前に、グローバル設定とプロジェクト内の指示ファイルを探索します。プロジェクト内では、プロジェクトルートから現在の作業ディレクトリまでを順に探索し、見つけた指示をルート側から結合します。

### 4.1 グローバル指示

Codex は、`CODEX_HOME` が設定されている場合はそのディレクトリ、設定されていない場合は通常 `~/.codex` をグローバル設定ディレクトリとして使用します。

このディレクトリでは、次の順に確認し、最初に見つかった空でないファイルを使用します。

1. `AGENTS.override.md`
2. `AGENTS.md`

グローバル指示には、複数のリポジトリで共通する個人または組織の方針を記述します。リポジトリ固有のビルドコマンドやパッケージ規則は、プロジェクト側へ記述します。

### 4.2 プロジェクト指示

Codex は、通常は Git ルートをプロジェクトルートとして扱い、現在の作業ディレクトリまでの各階層で次の候補を確認します。

1. `AGENTS.override.md`
2. `AGENTS.md`
3. `project_doc_fallback_filenames` に設定された代替ファイル名

各ディレクトリでは最初に見つかった空でない一ファイルだけを使用します。複数階層で見つかった指示は上位から下位の順に結合されるため、現在の作業場所に近い指示が、より広い範囲の指示より後に適用されます。

~~~text
repository/
├── AGENTS.md                 # リポジトリ全体の基本方針
├── src/
│   └── AGENTS.override.md    # src/ 以下で基本方針を補足・上書き
└── docs/
    └── AGENTS.md             # docs/ 以下の執筆規則を追加
~~~

例えば `src/` で作業する場合は、ルートの `AGENTS.md` に続いて `src/AGENTS.override.md` が適用されます。`docs/` で作業する場合は、ルートの `AGENTS.md` に続いて `docs/AGENTS.md` が適用されます。

### 4.3 読み込み上限と更新

空の指示ファイルはスキップされます。プロジェクト指示の合計サイズには `project_doc_max_bytes` の上限があり、既定値は 32 KiB です。指示を一つの巨大な手順書にせず、詳細資料へリンクしながら短く保ちます。

指示チェーンは Codex の実行ごとに組み立てられます。`AGENTS.md` を変更した後、進行中のセッションに古い指示が残っているように見える場合は、新しい Codex セッションで確認します。

## 5. 記述する内容

`AGENTS.md` には、リポジトリを安全かつ一貫して扱うために繰り返し必要となる情報を記述します。

### 5.1 推奨する内容

- 対象範囲とプロジェクトの目的
- 必須のランタイム、パッケージマネージャー、ビルドツール
- 調査、編集、差分確認の基本手順
- 実行するテスト、静的解析、フォーマット確認
- 生成ファイルや変更禁止領域
- コード、テスト、ドキュメントのプロジェクト固有規則
- ソースを変更するコマンドや破壊的操作に対する注意
- コードレビューで優先する観点

コマンドはコピーして実行できる形で記述し、「すべての変更で必ずフルビルド」のような過剰な指示を避けます。変更の種類ごとに、必要な検証範囲を判断できるようにします。

### 5.2 避ける内容

- API キー、パスワード、トークンなどの秘密情報
- 特定利用者の環境だけで有効な絶対パス
- すぐに古くなる一時的な作業状況
- 実際の設定と矛盾するバージョンやコマンド
- 詳細ドキュメントの長い複製
- 相互に矛盾する規則や、検証できない抽象的な要求

`AGENTS.md` はエージェントへの指示であり、OS のサンドボックスや権限管理を提供するファイルではありません。アクセス制御、秘密情報管理、実行権限は、Codex と実行環境の設定で別途管理します。

## 6. 階層別の指示を追加する

ルートの指示だけで十分な間は、`AGENTS.md` を増やす必要はありません。サブディレクトリで明確に異なる作業方法が必要になった場合だけ、より近い階層へ指示ファイルを追加します。

例えば、ドキュメント専用の規則を追加する場合は `docs/AGENTS.md` を作成できます。

~~~markdown
# Documentation Instructions

- Write prose in Japanese using polite style.
- Use tilde-style fenced code blocks.
- Verify relative links before handoff.
~~~

同じディレクトリの通常の `AGENTS.md` を一時的または明示的に置き換える場合は、`AGENTS.override.md` を使用します。上書きファイルには、変更する規則だけでなく、そのディレクトリで必要な前提が読み取れる内容を記述します。

## 7. 読み込みの確認方法

Codex CLI を利用できる環境では、リポジトリルートで次のように現在の指示を要約させて確認できます。

~~~bash
codex --ask-for-approval never "Summarize the current instructions."
~~~

特定のサブディレクトリに適用される指示を確認する場合は、`--cd` を使用します。

~~~bash
codex --cd docs/agent-plugins \
  --ask-for-approval never \
  "Show which instruction files are active."
~~~

確認時は、次の点を見ます。

- ルートの `AGENTS.md` が認識されている
- 対象ディレクトリに近い指示が後から適用されている
- 同じディレクトリでは `AGENTS.override.md` が優先されている
- 期待したコマンド、禁止事項、文書規則が要約に含まれている

## 8. 運用時の注意

`AGENTS.md` を変更する場合は、関連するビルド設定やディレクトリ構成と照合してください。例えば Java のバージョンを変更した場合は `build.gradle.kts` と指示を同時に更新し、検証コマンドを変更した場合は Gradle タスクが実在することを確認します。

Skill と重複する内容は、役割で分けます。リポジトリ内のすべての作業へ常に適用する短い方針は `AGENTS.md` に置き、特定の依頼でだけ必要となる詳細なワークフローは `SKILL.md` に置きます。

指示ファイルを追加しすぎると、適用範囲と優先順位が分かりにくくなります。新しいファイルを追加する前に、既存のルート指示を補足する必要が本当にあるか確認してください。

## 9. トラブルシューティング

### `AGENTS.md` が読み込まれない

1. ファイル名が大文字小文字を含めて正確に `AGENTS.md` であることを確認する
2. ファイルが空でないことを確認する
3. Codex の作業ディレクトリと、認識されているプロジェクトルートを確認する
4. 同じディレクトリに優先される `AGENTS.override.md` がないか確認する
5. 新しい Codex セッションで読み込みを再確認する

### 一部の指示が反映されない

1. より近い階層の指示が上位の規則を上書きしていないか確認する
2. 合計サイズが `project_doc_max_bytes` の上限を超えていないか確認する
3. 矛盾する表現や対象範囲が曖昧な表現を整理する
4. 長い説明を別のガイドへ移し、`AGENTS.md` からリンクする

### 別のエージェントで動作が異なる

`AGENTS.md` の探索方法と対応範囲はクライアントによって異なる可能性があります。本ガイドの探索順と設定名は Codex の公式仕様に基づいています。複数のエージェントで共通利用する場合は、各クライアントの対応状況を確認してください。
